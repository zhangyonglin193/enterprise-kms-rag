## 开场（30秒）

各位评委好，我汇报的项目是 **KMS 企业级知识管理系统**，甲方为银联商务。

这套系统面向银联商务内部知识管理场景，核心解决三个问题：
1. **权限管控** — 不同密级文档如何做到“不上读、不下写”
2. **流程内控** — 文档变更如何走工单审批，防止随意篡改
3. **知识检索** — 基于 RAG 的智能问答，如何避免召回过期冲突内容

系统中只有一类主体“员工”，工号格式为 2026+四位数字，初始密码为工号，便于展示登录。部门和职位参照银联商务实际组织架构设置。申请/审批角色仅在工单流程中出现，不是固定身份。

下面我从架构设计、核心创新、技术难点三个方面展开。

---

## 一、架构设计思路（1分30秒）

### 分层架构

系统采用五层架构：

- **接入层**：API 网关中间件，负责速率限制（60次/分钟滑动窗口）、全链路审计日志、请求 ID 注入。外部应用不能直接写入底层存储，所有文档变更必须通过接口发起工单。

- **路由层**：FastAPI 路由，分为管理路由、工单路由、知识路由、企业路由。

- **业务层**：核心业务逻辑，包括工单引擎、权限规则链、HR 同步、版本管理、归档存储。

- **领域层**：核心领域模型 — BLP 强制访问控制、文档悲观锁、工单状态机。

- **基础设施层**：MySQL 存储结构化数据，FAISS 存储向量索引，BGE-M3 做 Embedding，DeepSeek 做 LLM 问答。

### 权限模型简化

系统中最关键的设计决策是**权限模型简化**。

原来的系统有复杂的多角色体系 — 安全管理员、审计员、文档管理员、各类工单职责，还有临时提权机制。这导致权限判定逻辑分散，审计困难。

改造后，系统中**只有一类主体：员工**。权限判定仅依赖两个维度：
1. **安全职级 L0-L3**：由 HR 系统定义，KMS 只读引用
2. **所属部门**：决定文档归属

BLP 规则非常简洁：
- 读（不上读）：文档密级 ≤ 员工职级
- 写（不下写）：文档密级 ≥ 员工职级
- 部门：读需同部门或在开放列表，写需严格同部门

## 二、核心创新点（1分30秒）

### 创新 1：工单自动流转

传统工单系统需要人工指定审批人。我们的系统实现了**自动流转**：

员工上传文档后，系统根据文档密级和归属部门，自动筛选满足 BLP 规则的候选审批人。筛选条件是：安全职级 ≥ 文档密级 且 同部门 且 在职 且 非申请人本人。

这实现了"A/B 两权分立" — A 申请，B 审批，系统自动匹配 B，无需人工干预。

### 创新 2：文档悲观锁 + 两段式工单

同一文档同一时刻只允许一条在途变更工单。通过 MySQL 唯一索引 `uk_doc_id` 实现悲观锁。

工单采用两段式（申请 → 审批即执行），移除了原来的三段式（申请 → 审批 → 执行），因为审批通过后系统自动执行，不需要独立的执行人角色。

同时引入**差异化超时**：文档上传 72 小时、更新 48 小时、删除 24 小时，超时自动驳回并释放锁。

### 创新 3：归档向量库隔离

文档更新时，旧版本的 chunk 不是简单删除，而是移入**归档向量库**（kms_archive_chunks 表）。

RAG 检索阶段只从主向量库召回，自动排除已归档切片。这防止了 RAG 召回冲突内容 — 即同时召回新旧版本的矛盾信息。

归档数据保留可查，满足审计合规要求。

### 创新 4：HR 数据单向只读同步

KMS 不维护人事主数据。所有人员信息（工号、部门、职级、在职状态）从 HR 系统单向只读同步。

采用 upsert 策略，同步失败时使用旧缓存数据兜底，保证系统可用性。

## 三、技术难点（1分钟）

### 难点 1：BLP 规则的工程落地

BLP（Bell-LaPadula）模型是经典的多级安全模型，但工程落地有不少细节：
- 候选审批人的自动匹配需要同时满足职级和部门两个维度
- 权限规则链 `[OwnershipRule, BLPRule, DepartmentRule]` 的 AND 组合
- 审计日志的分级脱敏 — 不同职级看到不同详细程度

### 难点 2：哈希链防篡改

工单提交时计算 `original_hash`（申请内容的规范化 JSON SHA-256），审批通过时计算 `approved_hash` 并比对。如果中间 payload 被篡改，哈希不一致，工单标记为 `tampered` 状态，拒绝执行。

### 难点 3：版本管理与归档的一致性

文档更新时需要保证：旧 chunk 归档 + 新 chunk 入库 + 版本记录写入 这三步操作的原子性。我们通过文档锁保证同一时刻只有一个变更在进行，避免了并发冲突。

---

## 总结（30秒）

总结一下，本系统的核心设计理念是：

1. **极简权限模型** — 只有员工一类主体，BLP + 部门两个维度
2. **流程内控** — 文档变更全部走工单，自动匹配审批人，悲观锁防并发
3. **数据安全** — HR 只读同步、哈希链防篡改、归档向量库隔离
4. **可审计** — 全链路审计日志、分级脱敏、不可篡改
