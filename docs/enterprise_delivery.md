# 企业级 RAG 知识库升级 · 交付总结与上线准入

版本：2.0，2026-10-15。本文是面向银联商务甲方与竞赛评审的最终交付说明，与 `gateway_architecture.md`、`gateway_api_reference.md`、`../DEPLOY.md` 共同构成当前交付基线；其余 `docs/*.md` 为历史材料，不代表当前注册路由与安全边界。

## 0. 一句话定位

在保留原 FastAPI RAG 评测能力（`6341` 对外问答）的前提下，新增独立的“企业知识治理 + API 网关 + 办公渠道适配”层（`6342~6350` 本机受控），对标 IBM Content Navigator/FileNet 的文档级安全、Microsoft 安全多租户 RAG 的身份沿调用链与授权后入模、SAP API 管理的网关鉴权范式，形成金融合规优先、权限严格分级、审计全留痕、对外标准化 API、支持办公生态互通的单机受控试点实现。

> 本交付是“可直接答辩、可作为商用落地起点的受控试点版本”，不等于“已通过金融监管认证、无需甲方验收即可生产上线”。差距见第 6 节。

## 2. 原有优势保留与不合理点整改（摘要）

完整清单见架构文档第 3 节。核心结论：

保留并加强：
- `POST 6341/chat` 的 `question → answer` 评测契约不变，保证组委会 curl 测评不受影响。
- FAISS + BM25 + RRF + Rerank + LLM 的检索生成管线；混合检索与重排能力。
- MySQL 元数据 + 显式事务（`SELECT ... FOR UPDATE`）作为治理与审批的一致性底座。

整改与隔离（不再以“保留原逻辑”为名暴露不安全入口）：
- 取消注册“任意 HR 员工自报密级”的 HTTP 写入口，改为带审批编号的离线初始化 `scripts/bootstrap_employee.py`。
- 应用 Key 与员工 JWT 分离；浏览器只持短期令牌，Key 只在宿主 BFF 服务端。
- 企业问答改为单轮：拒绝 `session_id/use_history/end_user`，不复用旧答案缓存或历史。
- 模型出域默认关闭 `GW_MODEL_EGRESS_ALLOWED=0`；Rerank 前先回源授权过滤，未授权正文不送模型。
- 启动一致性从“只比数量”升级为比对实际 FAISS ID 集合、重复 ID、孤立分块；不一致拒绝启动、禁止自动删库“修复”。
- 发布/降密/归档/失效走双人策略（维护员与审批员名单互斥，不得自批、不得跨部门、拟定密级不超审批人）。
- 旧工单、流式、历史等入口保留源码但不注册路由，避免绕过新权限矩阵。

## 3. 银联商务三大场景适配

以下为能力边界说明，不代替业务、法务与合规部门的最终判断。

### 3.1 商户服务（入网、结算差错、操作指引）
- 知识按“部门 + 密级 + 文档状态 + 审批标记 + 有效期”多维授权：某分部操作员仅能检索本部门、本人密级范围内、已双人审批发布的《全民付蓝鲸入网手册》《B2B 网上支付操作手册》《D+1 结算产品手册》等。
- 渠道互通：坐席在飞书/企业微信私聊提问，经身份绑定映射到在职员工后，仅返回其有权内容；未绑定或停用员工拒绝降级匿名回答。
- 硬约束：商户个人敏感数据（卡号、身份证、结算账户）不得进入公共模型出域；默认关闭出域，需甲方书面批准并接入 DLP 后方可开启。

### 3.2 合规管理（政策依据、有效期、双人发布、审计留痕）
- 监管文件（如《银行卡收单业务管理办法》《非银行支付机构监督管理条例》《反电信网络诈骗法》及人行/原银监规范性文件）入库为草稿，须经独立审批员双人复核方可对相应密级发布。
- 文档有效期到期后自动从问答与目录中消失，防止引用失效政策；过期文档不得直接重新发布。
- 每次请求生成 `X-Request-ID`，开始/完成审计以 JSONL `fsync` 为强凭证、MySQL 为查询副本；审计不留空、失败即拦截业务或扣发答案。
- 边界：系统提供“有据可查、可复核”的检索与留痕，不输出法律意见，合规结论仍需合规部门审定。

### 3.3 链上商务（流程与智能合约文档的知识辅助）
- 面向《智能合约介绍》《Web3 支付产业研讨》《Interoperable QR Code Payment Ecosystem in ASEAN》等，作为“文档问答/流程指引”知识助手，按密级授权内部研究人员。
- 严格只读知识辅助：系统不签名、不转账、不发起或执行任何链上交易、不持有私钥；链上操作必须由独立授权的交易系统与安全审批完成。
- 跨境/涉密资料按部门与密级隔离，未审批发布内容不出现在检索结果中。

## 4. 答辩演示顺序（可直接照读）

端口与身份约束：`6341` 无员工认证（仅公开竞赛资料），`6342` 为企业门户/治理/渠道/嵌入 API。

1. 评测契约：`curl -X POST http://<host>:6341/chat -d '{"question":"..."}'` 返回 `{"answer":...}`，证明升级未破坏组委会测评口径。
2. 员工登录：`6342` 门户以离线初始化的批准工号登录，签发 1 小时 JWT（issuer/audience/jti）。
3. 草稿与双人发布：L3 维护员上传→系统置为本部门草稿（不可对外）→独立审批员批准发布；演示维护员自批被 403、跨部门被拒、文档快照变化被 409。
4. 授权问答：同员工提问，仅返回密级/部门/状态/有效期交集内资料；演示 Rerank 前对未授权分块的过滤。
5. 越权拒绝：低密级/跨部门/草稿/过期/未审批资料不出现在答案与目录；仅持应用 Key 无员工态最多读已发布 L0。
6. 令牌与撤销：登出或改密后旧 JWT 立即失效；长问答返回前二次复核撤销状态。
7. 审计：`/admin/audit-events`（仅审计员）按 `request_id` 追溯一次请求的开始/完成/下游。
8. 渠道与嵌入边界：演示飞书/企微回调仅受理已绑定在职员工的私聊文本并异落入队；BFF 持服务端 Key、浏览器不接触 Key。
9. 统一登录与目录：`GET /kms/api/auth/sso/authorize` → 内置 IdP 302 授权码流登录；`KMS_OIDC_PROVIDER=external` 时 `POST /kms/api/auth/sso/exchange` 用外部 `id_token`（JWKS 验签）换 KMS JWT；`GET /kms/api/auth/me` 返回组织字段（`org_path` / `org_node_id` / `manager_employee_no`）。
10. 定向推荐：`GET /kms/api/recommendations` 返回带 `reasons` 的推荐，且**仅包含本人有权访问**的文档；用低职级账号演示越权候选被硬过滤剔除。
11. 上线边界：明确当前为单机受控试点，Linux/MySQL/平台/压测为待验收项（第 6 节）。

## 7. 端口与数据硬约束（不可突破）

- `6341`：QA 评测主服务，唯一对外暴露入口，端口不可改、不作他用。
- `6342~6350`：KMS、企业网关、Webhook、嵌入服务/BFF 等附加服务；默认 `6342`（KMS+网关本机），示例 BFF `6343`。
- 严禁任何程序把非 `6341` 端口作为“主服务”，严禁新建/抢占 80/443 等监听入口。
- 端口冲突即退出，不改端口、不按进程名杀进程；仅用受控启动器 `scripts/service.py`/`scripts/manage.py`。
- QA 与 KMS 必须使用不同数据库名、且 FAISS/上传/文档三类目录互不相同且互不包含；生产 DB 账号分别授权。
- 凭据仅经 `.env` / `.env.kms` 注入，严禁写入代码或示例文件明文：新增 `KMS_LDAP_BIND_PASSWORD`（只读绑定口令）、`KMS_OIDC_CLIENT_SECRET`（外部 OI 平台客户端密钥）均为空占位，实测值只在部署机本地填写，不入版本库。

## 9. 已知技术债（不阻塞交付，但需在商用前处理）

- 密码策略：`hash_password` 仍接受 6 位，HTTP 与初始化工具要求 12 位，需统一。
- 改密与 SQLite 撤销跨存储非原子，登录/改密并发存在竞态，需专项测试与收敛策略。
- 登录失败限流桶缺全局上限与线程安全治理；各功能临时 `MySQLStore()` 各自建池，连接资源未统一。
- 早期鉴权失败若发生在 CORS 之前可能缺 CORS 头；无请求体读取总超时与并发响应内存硬上限。
- 单机 daemon worker 退出仍可能中断投递，租约恢复可能重复；无申请取消/超时关闭/独立有效期变更/完整版本树。
- 清理为业务触发而非定时服务；无磁盘加密、集中告警、多副本。

以上债务均已在代码注释或本基线文档标注，不作为“已完成商用”的依据。
